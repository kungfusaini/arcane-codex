Research note

Arcane Codex publishing system — current state

The current setup is a single app with a single global publishedMode flag. It does not really have two separate systems; it has one workspace that can route into either a private namespace or a published namespace.

What the current system is

Publishing is controlled by one boolean stored in the settings table: publishedMode. When it is true, normal private routes redirect into /published. The published routes themselves always exist and render a read-only view of the same data.

In other words: publish mode is a routing/state toggle, not a separate deployment or data model.

How it works

State storage SQLite settings row via getSettings() / updateSettings() in src/lib/data/storage.ts.
Toggle source The sidebar button calls PATCH /api/settings with { publishedMode: true|false }.
Private route behavior src/app/page.tsx, src/app/page/[[...pagePath]]/page.tsx, src/app/collections/page.tsx, and src/app/collections/[collectionId]/page.tsx redirect to /published variants when the flag is on.
Published route behavior src/app/published/** always renders read-only pages and collections. These routes do not check the flag before rendering.
Client-side navigation toWorkspacePath() in src/lib/workspaceMode.ts maps a current path into the matching private or published path after the toggle changes.
Editing restrictions Most UI components accept a readOnly prop and hide editing controls, but the API routes themselves do not enforce published mode.

Route map

/                      private home, redirects to /published if publishedMode is on
/page/...              private page route, redirects to /published/... if publishedMode is on
/collections           private collections index, redirects to /published/collections if publishedMode is on
/collections/...       private collection route, redirects to /published/collections/... if publishedMode is on

/published             published home, always read-only
/published/...         published page route, always read-only
/published/collections published collections index, always read-only
/published/collections/... published collection route, always read-only

If your deployment rewrites /published to /public, that is deployment-level behaviour, not the app code itself.

What is good about it

  • Very simple to understand: one flag, one database row, one toggle.
  • Both views share the same content and structure, so there is no data duplication.
  • Published mode is covered by browser tests.
  • The same page URLs can be rendered in private or published form with minimal branching.
  • Read-only UI state is centralized through readOnly props instead of scattered ad hoc checks.

What is bad or messy

  • It is not a real separation between editor and published site; it is one app with two route namespaces.
  • The published namespace is always live, even when publishedMode is off.
  • The sidebar still exposes the master publish toggle in published mode, so the live site can switch the workspace back to private.
  • Mutation APIs like /api/pages and /api/collections do not check publish state, so read-only is mostly a UI convention, not a hard server boundary.
  • Route logic is duplicated across private and published files, which makes maintenance awkward.
  • The naming mixes concerns: the toggle name, route namespace, and deployment story are all slightly different, which makes the system harder to reason about.

Short diagnosis

The current design is functional, but it is really a mode switch, not a clean publish architecture. The editor and live site are coupled at the routing and database layer, and the UI still leaks control back into the published experience.

That is why it feels messy: the system is doing two jobs at once.

Files that define the system

  • src/lib/data/storage.ts — persisted publishedMode setting
  • src/app/api/settings/route.ts — toggle endpoint
  • src/components/WorkspaceSidebar.tsx — publish toggle UI and redirect
  • src/lib/workspaceMode.ts — private/published path mapping
  • src/app/page.tsx and src/app/page/[[...pagePath]]/page.tsx — private page redirects
  • src/app/collections/page.tsx and src/app/collections/[collectionId]/page.tsx — private collection redirects
  • src/app/published/** — published read-only route tree
  • src/app/api/pages/route.ts, src/app/api/pages/[id]/route.ts, src/app/api/collections/route.ts — mutation APIs that currently ignore publish state
